保留期尚未自动执行

retention_until 是软到期字段，仓库未发现定时物理删除或匿名化任务。

先挡噪音，再回答“能否落到产品”

电商用一个结构契约；社媒依次经过 G1–G5。G 系列解决准入与归属，R0–R3 再给统一证据集一个封闭的分类结果。

两个“终态”不要混为一谈

  • 业务门终态品牌、竞品组、内容标签、官号、无价值、诉求过泛、缺陷不可归属等，主要进入运行指标。
  • 证据终态账voc_unclassified_evidence 记录 unclassified、vote_dropped、truncated、generation_failed、grounding_rejected。
  • 分类无效R0 / R3 是机会分类结果，不是第三种机会类型。

来源与产品归属正交

  • fact云听直接标注的 SPU，属于事实。
  • root同组根帖唯一指向的 SPU，只用于推断挂载。
  • 特殊规则社媒诉求若只有 root 继承 SPU，会降为无 SPU 进入创新；避免把泛诉求绑死到帖子背景产品。
05
v3 的守恒锚点

把每轮归属冻结成不可变快照

所有下游都读取同一个 run_id 快照，而不是在不同阶段重新展开会变化的 message.spu 数组。这是路由、机会关系、终态账和 SPU 派生能对上账的前提。

单写者advisory lock

voc_prepare_assign_snapshot() 串行准备同一轮快照，重复调用幂等。

不可变禁止 UPDATE

删除必须按整个 run_id 处理；writer 不能绕过准备函数直接写入。

可验证三项指纹

行数、不同事实数与内容 MD5 写入 run log，finalize 前重新计算。

可追溯关系保留归属

voc_opp_evidence 写 assigned_spu、assignment_source、assign_run_id。

冻结快照解决了什么问题
旧风险：二次展开

如果生成、关系写入和派生刷新分别读取可变数组，同一证据可能在不同阶段得到不同 SPU 集合，造成错挂、漏挂和不可解释的四象限差异。

当前契约：单一投影

路由集合与快照双向差集必须为空；关系行也必须来自同一快照。机器事实以后变化，只影响下一轮，不污染本轮。
