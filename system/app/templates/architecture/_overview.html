01
一分钟看懂全系统

一条 VOC 如何变成可行动的产品机会

系统的核心不是“让模型写一张卡”，而是让每条声音沿着同一份事实、同一轮冻结归属和可对账的终态，最终进入机器机会层或明确停止。

01来源不决定生命周期

src_line 只表示在哪里发现；是否必须有 SPU 由来源策略决定。

02模型不改写事实

根帖继承是推断归属，始终与云听直接标注的 fact 分开保存。

03同卡与共性是两层问题

基础机会身份不跨 SPU；跨产品规律由战略派生层表达。

04人工语义不被机器覆盖

机器层、人工层和审计日志分离；状态受数据库触发器约束。

02
系统上下文

五个组件，只通过明确边界交接

pipeline 与 system 是两个 Python 项目，不经 HTTP 互调；PostgreSQL 是机器生成、派生读取和人工回写的唯一交接面。

组件职责与失败边界
组件输入负责输出 / 边界状态
云听 CEM查询条件与时间窗外部检索、导出 XLSX原始消息、标签与产品字段已接入
pipeline导出文件、数据库、百炼事实入库、机会生成、派生刷新机器表、运行账、战略轴仓库已实现
PostgreSQL机器与人工写入约束、触发器、物化视图、审计唯一共享数据面实库待核验
system数据库与飞书身份列表、详情、状态更新、战略浏览HTML / HTMX 页面仓库已实现
外部调度与提醒计划任务、SLA 事件定时运行、失败告警、PM 催办当前没有内置实现产品规划
不是微服务

没有队列、事件总线、Redis 或对象存储。复杂度集中在 PostgreSQL 契约与离线 supervisor。

不是实时流

当前是手工批处理；页面展示的是已经落库的结果，不订阅上游实时事件。

不是多租户

所有授权用户共享一个数据池；owner 是业务字段，不是行级权限边界。
