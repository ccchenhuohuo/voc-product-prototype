### 2.3 测试

每项代码改动配回归测试，最低要求：

- 分块键改造：同一 SPU 的电商 + 社媒证据进同一桶；多 SPU 证据进多个桶
- 身份契约：新品 `core_tag` 为 `NULL`，同一 `problem_mode` 幂等
- 守恒等式：给定证据集，`R == F`，且每个 opp 的 `assigned_spu` 唯一等于其 `core_tag`
- `voc_has_spu` 覆盖四种状态：仅事实 / 仅继承 / 两者都有 / 两者皆空
- 兼容视图：切换前后 `voc_spu_issue` 的列名与类型一致
- **落库写入**：`save_opportunity()` 写出的关系行四列齐全；`execute._merge()` 复制后不丢
- **新品不进 L1**：行为测试断言 worker 里新品的 `resolve_one` 不调用 `l1_candidates`
- **快照单写者与幂等**：两个进程用同一 `run_id` 并发调用准备函数，结果只有一份、
  行数一致；**第二次调用返回既有行数且不报错**——幂等是为了让失败重试能恢复，
  不是「二次写入被拒绝」（那会让重试卡死）。另断言不同 `run_id` 的两份快照互不影响
- **不得删除或放宽现有 223 个测试中的任何一个**；如某测试因契约变更必须改，
  在提交说明里逐条列出「改了什么、为什么这不是放宽」
