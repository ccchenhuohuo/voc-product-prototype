## §1 数据流总览

```
voc_opportunity（classification_state='确定'，merged_into IS NULL，mode_vec 非空）
   ├─ opp_type='老品迭代' ─┐
   └─ opp_type='新品创新' ─┤ 分别独立聚类（同一套机制，两套参数/提示词）
                           ▼
        ① 召回：pgvector 每卡 top-K 近邻，cos ≥ STRATEGY_MERGE_COS
        ② 判定：贪心 leader（镜像 stage1.merge_similar_modes，非传递闭包），
           每对是否同轴由 LLM 判定，判定结果写缓存表，复跑不重付
        ③ 命名：每个多卡簇一次 LLM 调用，产出轴名 + 一句话摘要
                           ▼
        voc_strategy_axis / voc_strategy_axis_member（单事务全量重建）
                           ▼
        system：/strategy 总览（通病｜诉求两个 tab）→ /strategy/axis/{axis_id} 详情
```

**为什么是贪心 leader 而不是传递闭包**：2026-08-20 预演，1,006 张老品卡上
并查集在 cos≥0.65 把 987 张串成一簇（A~B、B~C 推出 A~C 的链式污染）；
贪心 leader 在 0.75–0.80 产出可读的轴（"塑料承力件强度不足 跨62 SPU"等）。
**为什么召回后必须 LLM 判定**：同一预演实测，纯余弦在 0.75 会把
"伸缩杆晃动"（缺陷）与"增加最大伸展高度"（增强诉求）误合——几何分不开，
语义分得开。

沿用 030–033 的防护头（`voc_admin` 守卫、`SET LOCAL search_path`、事务包裹）。

**幂等必须真的可重跑**：下面的示例 DDL 写的是无条件 `CREATE`，第二次执行必炸。
实现时一律用 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` /
`CREATE OR REPLACE FUNCTION`；对已存在但列不全的表用
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 补齐。仅写"可重跑"不算交付。

**授权不得省（031/032 都显式授权，034 漏了就是建完也读写不了）**：应用以
`voc_human` 连接（`system/app/db.py`），管线以 `voc_writer` 连接

  （若实现用 upsert 则加 `UPDATE`）
- `voc_human`、`voc_reader`：轴表与成员表 `SELECT`
- 判定缓存**不对 human/reader 暴露**（页面不需要它）
- 序列/自增对象如有，一并授权

§6 增加静态授权契约测试（扫 034 文本断言上述 GRANT 存在）——否则路由 smoke 的
fake DB 会把生产权限错误完全遮住。

```sql
CREATE TABLE public.voc_strategy_axis (
  axis_id     text PRIMARY KEY,          -- md5(generation||'|'||axis_type||'|'||join(sort(member opp_ids),','))
  generation  text NOT NULL CHECK (generation IN ('OPP-','OPP2-')),  -- §3.1 发布代次
  axis_type   text NOT NULL CHECK (axis_type IN ('通病','诉求')),
  axis_name   text NOT NULL,             -- LLM 产出，≤24 字，禁分类名
  summary     text,                      -- LLM 产出一句话，≤60 字；失败可为 NULL
  n_cards     int  NOT NULL,
  n_spu       int,                       -- 通病：distinct SPU 数；诉求恒 NULL
  n_eff       numeric,                   -- 通病：(Σw)²/Σw²，w=各 SPU 证据数；诉求恒 NULL
  evi_total   int  NOT NULL,             -- 成员卡证据行合计
  prod_lines  text[] NOT NULL DEFAULT '{}',   -- 实测全空（§9），落库保留、界面不展示
  categories  text[] NOT NULL DEFAULT '{}',   -- 实测 103/1006，同上
  top_spus    jsonb,                     -- 通病：[{"spu":..,"evi":..}] 按证据数前 STRATEGY_TOP_SPUS
  run_id      text NOT NULL,
  computed_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ix_strategy_axis_type ON public.voc_strategy_axis (axis_type, n_eff DESC NULLS LAST);

CREATE TABLE public.voc_strategy_axis_member (
  axis_id       text NOT NULL REFERENCES public.voc_strategy_axis ON DELETE CASCADE,
  generation    text NOT NULL,           -- 冗余，与父轴一致
  axis_type     text NOT NULL,           -- 冗余，与父轴一致
  opp_id        text NOT NULL,
  role          text NOT NULL CHECK (role IN ('leader','member')),
  cos_to_leader numeric,                 -- leader 行为 1.0
  link_spu      text,                    -- 老品成员的详情页链接键（§4.2），诉求为 NULL
  PRIMARY KEY (axis_id, opp_id)
);
-- 冗余列必须真被数据库约束与父轴一致，否则"分区不变量"只是注释里的口号
ALTER TABLE public.voc_strategy_axis
  ADD CONSTRAINT ux_strategy_axis_identity UNIQUE (axis_id, generation, axis_type);
ALTER TABLE public.voc_strategy_axis_member
  ADD CONSTRAINT fk_strategy_member_axis
  FOREIGN KEY (axis_id, generation, axis_type)
  REFERENCES public.voc_strategy_axis (axis_id, generation, axis_type) ON DELETE CASCADE;
-- 分区不变量：同一代次同一类型下，一张卡只能属于一个轴
CREATE UNIQUE INDEX ux_strategy_member_once
  ON public.voc_strategy_axis_member (generation, axis_type, opp_id);
CREATE INDEX ix_strategy_member_opp ON public.voc_strategy_axis_member (opp_id);

-- LLM 判定缓存。键必须含判定策略版本：否则改了提示词，旧对全部命中、
-- 新提示词永远不生效（§3.3 冻结决议 13）。
CREATE TABLE public.voc_strategy_pair_verdict (
  opp_a        text NOT NULL,            -- 约定 opp_a < opp_b
  opp_b        text NOT NULL,
  mode_hash_a  text NOT NULL,            -- md5(problem_mode)
  mode_hash_b  text NOT NULL,
  judge_policy text NOT NULL,            -- md5(判定提示词模板 + 模型名)，随提示词变更自动失效
  same         boolean NOT NULL,
  judged_at    timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (opp_a, opp_b, mode_hash_a, mode_hash_b, judge_policy)
);
```

原设计把 `model` 单独存一列却不参与命中条件，等于没有作用；现改为把提示词模板
与模型名一起哈希进 `judge_policy` 并纳入主键。§5 运维说明里"改了提示词要手动
重跑"随之改为"改了提示词缓存自动失效，重跑即可"。

不加轴的历史/趋势表，不给轴挂任何人工状态列——**轴是纯派生读模型**，
PM 的跟踪状态只存在于成员卡上（老品 issue 状态、新品 status），全量重建才安全。

## §3 管线模块：voc_analytics/strategy.py

### 3.1 输入与排序

两类分别取卡：`opp_type` / `classification_state='确定'` / `merged_into IS NULL` /
`mode_vec IS NOT NULL`。不按工作流状态过滤（已解决的卡仍计入扩散面，详情页展示其状态）。

**必须冻结发布代次（冻结决议 11）**：v3 灰度期 `OPP-*` 与 `OPP2-*` 同表并存
（`pipeline/docs/施工任务书_v3.md:182-184`），而两个 `voc_spu_issue` 版本各含一代
（`pipeline/sql/032_spu_issue_v2v3.sql`：v2 过滤 `OPP-*`、v3 过滤 `OPP2-*`）。
若输入不限代次，会把两代机会点混在一起聚类——另一代老品卡权重变 0，
另一代新品卡则直接重复进轴。**这不是透明切换，是混代产轴。**

处置：新增配置项 `STRATEGY_GENERATION`（取值 `OPP-` / `OPP2-`，默认 `OPP2-`），
同一个值必须同时作用于：通病输入、诉求输入、`voc_spu_issue` 证据计数的 join，
以及 `run_strategy.py` 的 `--generation` 覆盖参数。轴表落 `generation` 列，
前端只读当前代次的轴。§6 增加回归测试：两代卡同时存在时，产出的轴成员
必须全部同代。

每卡先算权重 `evi_total`：
- 老品：`SELECT opp_id, sum(evi_count) FROM voc_spu_issue GROUP BY 1`
  ——**必须读 `voc_spu_issue` 这个兼容视图名**（032 起它是普通视图，指向 v2 或
  v3 物化对象），禁止自己 join 消息数组重算。**但切换对本模块并非透明**：
  兼容视图指向哪一代，`STRATEGY_GENERATION` 就必须同步指向哪一代，两者不一致
  会产出"老品权重全 0、新品照常成轴"的混代结果。§6 测试 11 就是验这个。
- 新品：`SELECT opp_id, count(*) FROM voc_opp_evidence GROUP BY 1`。

聚类迭代顺序冻结为 `(evi_total DESC, opp_id ASC)`——证据多的卡当 leader，
且同输入必得同输出（测试 §6 会验确定性）。

### 3.2 召回

pgvector：对每卡取同类型内 top `STRATEGY_TOPK` 近邻，保留 `cos ≥ STRATEGY_MERGE_COS`，
对 `(a,b)` 归一化为 `a<b` 去重。召回对数超过 `STRATEGY_MAX_PAIRS` 时**硬中止**、
不写任何表、退出码非 0 并打印实际对数——这是 v3 卡数不确定情况下的花费保险丝。

### 3.3 贪心 leader + 判定

镜像 `merge_similar_modes` 的结构，差异只有三点：
1. 相似度来自召回结果的字典（不重复 embed——直接用库里 `mode_vec` 算好的 cos）；
2. 判定前先查 `voc_strategy_pair_verdict` 缓存，未命中才调 LLM 并写回；
3. 无 `MAX_GROUP_SIZE` 约束（轴不喂 Stage2，不存在 88 人组事故的复现条件）。

**保留母本的惰性判定，不改成"先判完全部召回对"（冻结决议 12）**：
母本会跳过已并入其他 leader 的 i/j（`stages/stage1.py:414-431`），只对当时仍未
归并的 pair 调 LLM。A 吸收 B 之后 B–C 的判定结果用不上，先判全部纯属白烧。
迭代顺序已冻结为 `(evi_total DESC, opp_id ASC)`，所以惰性判定同样是确定性的。

代价是**判定次数 < 召回对数**，因此台账与验收口径按实际评估数记，不得写成
"判定数 = 召回对数"：
- 台账记 `pairs_recalled`（去重后召回对数）、`pairs_evaluated`（实际取用的对数）、
  `verdict_cache_hits`、`llm_judged`，满足 `pairs_evaluated = cache_hits + llm_judged`
  且 `pairs_evaluated ≤ pairs_recalled`
- §7 验收等式相应改为上面这条，不再要求等于召回对数
- §9 的成本估算读作**上界**：老品 ≤3,076 对、新品 ≤1,010 对

**判定失败不得落成正常缓存（冻结决议 13）**：重试耗尽按"本轮不合并"处理并计数，
但**不写 `voc_strategy_pair_verdict`**——否则一次瞬时故障会把两条本该合并的轴
永久判成不同。冻结决议 5 是"本轮不合并"，不是"永久判不同"。

### 3.4 提示词（prompts.py 追加，两个，返回 JSON）

`STRATEGY_AXIS_SAME`（通病判定，required=["same"]）要点：
- 问题：两张 SPU 级问题卡是否属于**同一公司级共性问题轴**（同类根因/同类改进方向，
  允许载体不同：脚管扳扣打滑与中轴锁定松动同属"锁定机构失效"）
- **红线：缺陷与增强型诉求不得判同**——"伸缩杆全高晃动"（现状失效）与
  "希望更高的伸缩杆"（现状不满足期望）必须 same=false。预演实测这是纯余弦的
  头号误合来源，提示词里必须给这组反例。

`STRATEGY_THEME_SAME`（诉求判定，required=["same"]）要点：
- 问题：两张诉求卡是否指向**同一核心诉求主题**
- **红线：方向相反的诉求不得判同**——"希望更小更轻"与"希望更大更稳"
  embedding 距离近，必须 same=false，提示词给反例。

`STRATEGY_AXIS_NAME`（两类共用，required=["axis_name"]）：输入成员卡的
problem_mode 列表 + 品线分布，输出 `axis_name`（≤24 字）与 `summary`（一句话 ≤60 字）。
axis_name 过 `validate.check_problem_mode` 同款的泛化名校验，命中"××类"这种
分类名则重试一次，再失败回退用 leader 卡的 problem_mode 原文。

### 3.5 成轴与落库

准入：通病轴 `n_spu ≥ STRATEGY_MIN_SPU`（distinct SPU 来自成员卡 join `voc_spu_issue`）；
诉求主题 `n_cards ≥ STRATEGY_MIN_CARDS`。不达准入的簇（含单卡簇）不落库——
它们已在老品/新品两页各自可见，战略页只收宏观聚合。

**`n_spu` 口径不得擅改（冻结决议 9）**：`voc_spu_issue` 带
`HAVING count(DISTINCT message_id) >= 2` 的门——某 SPU 上要有两条独立声音
才算确证挂载。后果是它只覆盖 337/1006 张老品卡、128 个 SPU（§9 实测）。
**这是特性不是缺陷**：改成从 `voc_message.spu||spu_inherited` 原始展开会把
"该 SPU 上只出现过一次"的噪声算进扩散面，实测同一张卡的扩散度会从 27 虚涨到 93。
成员卡在 `voc_spu_issue` 中无行时，该卡照常参与聚类（它对轴的语义有贡献），
只是对 `n_spu`/`n_eff`/`evi_total` 贡献 0，且 `link_spu` 为 NULL、详情页该行不给链接。

通病轴聚合列：`n_spu`、`n_eff=(Σw)²/Σw²`（w = 该 SPU 上成员卡 `evi_count` 之和，
公式与 026 一致）、`top_spus`、`categories`（成员卡 category 去重）。
诉求主题：`n_cards`、`evi_total`、`prod_lines`（成员卡 prod_line 去重）。

落库：**按 `(generation, axis_type)` 分区替换，不是无条件删全表**（冻结决议 14）。
`--type 通病` 只替换通病分区、绝不动诉求分区，反之亦然；`--type all` 在同一事务
内替换两类。原文写的"DELETE 全部旧行"与 `--type` 参数直接冲突——单类型运行会
删掉另一类且不重建。§6 增加回归测试证明单类型运行不改变另一分区。

替换在**同一事务**内完成——失败自动回滚，页面永远不会读到半新半旧。
`axis_id = md5(generation||'|'||axis_type||'|'||成员 opp_id 排序拼接)`，
成员不变则 ID 稳定，书签与外链在常规重算下不断。

运行台账写 `voc_run_log`（复用 RunCtx 机制），至少含：
`pairs_recalled / verdict_cache_hits / llm_judged / llm_failed / axes_written /
members_written / llm_calls / llm_tokens`。

### 3.6 配置（config.py，注释风格对齐现有）

```python
STRATEGY_MERGE_COS = 0.75   # 召回阈值；2026-08-20 预演 0.80 碎裂/0.75 靠 LLM 挡误合
STRATEGY_TOPK      = 15     # 每卡近邻上限；对数上界是 min(n*K, n*(n-1)/2)，

STRATEGY_MIN_SPU   = 2      # 通病轴准入
STRATEGY_MIN_CARDS = 2      # 诉求主题准入
STRATEGY_TOP_SPUS  = 10     # top_spus 存前 N
```

## §4 系统层

### 4.1 /strategy 总览（strategy.html 重写）

结构对齐 board.html：`header.head` + tabs + `.scroll > table`。
tabs = 「跨SPU通病 N」「核心诉求 M」（替换现在的 品线级/多品/单品/全部——
scope 口径整体退役）。

## §9 探针实测（2026-08-20，只读，未写库）

**算法选型**：1,006 张老品卡上，并查集（传递闭包）在 cos≥0.65 把 987 张串成

贪心 leader 后行为正常，故冻结决议 1。

**新品（诉求）**：964 张卡全部有 `mode_vec`。0.75 下 634 簇 / 161 多卡簇 /

18/29、快装板安全与通用性 11/28、配色选择过少 8/26、新品上市时间无官方渠道 15/24。

**纯余弦的误合实例**（证明冻结决议 1 的"LLM 判定不可省"）：
- 老品 0.75：「伸缩杆：增加最大伸展高度」（增强诉求）被并进「伸缩杆全伸展晃动」（缺陷）
- 老品 0.75：「强化单手操作能力」（易用性）被并进「降低整体体积重量」
- 新品 0.75：「摄影背心上市时间」与「摄影背心挂载接口」合成一条
- 新品 0.75：「内置电池」「散热降频」「电量显示」三件事合成一条

这四例必须成为 §3.4 两个判定提示词的反例素材，也是 §6 测试 3 的 fixture 来源。
